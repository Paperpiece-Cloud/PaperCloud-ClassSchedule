# PaperCloud

一个为班级 49 人做的班级门户网站：课表、值班、班级管理、在线工具、校园 720° 全景。

纯 Python 标准库后端 + 原生前端，**不依赖任何 Web 框架**，跑在一台 Windows 云电脑上。

---

## 功能

| 模块 | 说明 |
|---|---|
| **首页** | 通知、校园航拍轮播、全景入口 |
| **课表** | 周课表、单双周、教师/教室，支持导出 ICS 日历 |
| **班级** | 通讯录、分组、值班安排 |
| **控制台** | 值班状态、访客统计、在线人数 |
| **管理后台** | 课表调整、调课记录、公告 |
| **快捷调课** | 教室/课时调整，滑动确认，长按撤销 |
| **工具箱** | 若干班级常用小工具 |
| **720° 全景** | 自研 WebGL 立方体全景，双场景 + 建筑标注 |

---

## 技术栈

**后端**

- Python 3 标准库：`http.server` / `ThreadingHTTPServer`
- 手写路由、Cookie 会话、`pbkdf2` 密码哈希
- 自实现 gzip（`Accept-Encoding` 协商）
- 数据存 JSON 文件，无数据库

**前端**

- 原生 HTML / CSS / JavaScript，无框架、无构建
- iOS 液态玻璃视觉（`backdrop-filter` + 多层阴影）
- CSS 动画为主，轮询获取数据

**全景**

- 自研 WebGL1 渲染器：六张立方体贴图拼接天空盒
- 拖动/惯性/双指缩放，标签按球面角度投影到屏幕坐标

## 目录结构

```
app/            后端（路由、会话、各业务模块）
web/            页面（每个页面一个独立 .html）
  campus/       校园航拍图
  tour2/        全景（场景图不在仓库里）
data/           运行时数据（只提交 *.example）
config/         配置（只提交 *.example）
```

---

## 本地运行

```bash
python app/server.py
# 默认监听 http://127.0.0.1:8787
```

配置：复制 `config/secrets.example.json` 为 `config/secrets.json`，填入自己的口令。
数据：复制 `data/*.example` 为对应的 `.json`。

## 设计取舍

**为什么不用 Django / Flask**

部署环境是一台 Windows 云电脑，装依赖、配数据库都麻烦。标准库零依赖，拷过去就能跑。

**为什么用 JSON 文件而不是数据库**

49 人规模，写入频率极低。真要做大，第一步换 SQLite（单文件、免安装）。

**为什么自己写全景而不是用第三方播放器**

原方案是 720yun 导出的 krpano 播放器，4.3 MB，缺一个资源文件就整页白屏。自研版本约 20 KB，损坏时只影响单个面。

**为什么用轮询而不是 WebSocket**

课表、值班这类数据几分钟才变一次，长连接不值得维护，还容易在校园网下断线。

---

## 已知不足

- 管理接口没有 CSRF token
- 没有请求限流
- 数据文件无并发写保护（人多时需要迁移到 SQLite）
- 部署靠手动拷文件，没有 CI
